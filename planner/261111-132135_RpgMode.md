## Decisions (do not ask)

1. World operations are **RPG tools** defined in `src/rpg/tools.rs` (a typed table → JSON schemas, args parsed into typed structs with serde), **not** new `Ops` variants. `Ops` run on a chat `Context` that has no session `Store`.
2. Query-tool results go into scratch registers R4–R15 via `context.registers.allocate` and the model gets the receipt, as `src/tools.rs` does. Mutate tools return a short inline receipt such as `aspect #142 added`. The narrator also gets `reg_view` and `reg_search` (run through `crate::tools::execute`) and every project word in `context.user_words` (also through `crate::tools::execute`). That is how per-session words in `_forgeflow/rpg/<session>/world_words.ff` reach the narrator: `user_words::load` already loads every `.ff` file below `_forgeflow`. No new loading code.
3. The RPG session gets **its own `Context`** with in-memory registers and memory (`Registers::in_memory()`, `Memory::in_memory()`), so it never touches the chat's `registers.json`. It borrows the chat's llama-server with `context.server.take()` and hands it back on exit.
4. Game time is a fixed-format string `YYYY-MM-DDTHH:MM` (16 characters, checked by hand, no regex crate). Strings in this format compare correctly as text, so the SQL uses text comparison. A new world starts at `1471-03-12T20:00`.
5. "Append-only": the only `UPDATE`s allowed are closing a row (`valid_to`, `superseded_by`, `ended_event_id`, `left_event_id`), setting `chain_root_id = id` on a new root row, and `stress_tracks.marked` (scene state, as the design says). Everything else is an `INSERT`.
6. A root row has `chain_root_id = id`; a successor copies its predecessor's `chain_root_id`.
7. `add-aspect` auto-supersedes only when `slot` is set: the current aspect with the same holder (NULL-safe `IS`), scope and slot is closed. Aspects without a slot never conflict.
8. `valid_from` for new rows defaults to the session's current game time. A given `valid_from` must be ≥ the current game time and ≥ the predecessor's `valid_from`.
9. `log-event` takes `game_time`, `summary`, optional `actor_id`. The turn number is derived (`meta.turn + 1`), not an input. A `game_time` later than the current one advances `meta.game_time`; an earlier one (a flashback) does not.
10. `run_turn` itself logs one event per turn first: summary `Player: <action>` (first 200 characters). The event spine is then never empty.
11. Extra mutate tools beyond the design's list, needed so the world can grow: `add-entity`, `add-behavior`, `add-stress-track`. Without them the narrator and archivist cannot add a new NPC.
12. `begin-scene` participants are objects `{"entity_id": 1, "role": "pc"}`. `begin-scene` also takes an optional `summary`. Roles are `pc`, `npc`, `prop`, `observer`.
13. `end-scene` carry-over moves each listed situation aspect to the scene's location (close the old row, insert the successor with `holder_id = location`, same chain). A non-empty `carry_over` on a scene without a location is an error. Every other current situation aspect of the scene expires. Every current presence row **of that scene** closes; presence in other scenes is untouched.
14. Flashback: a scene with `valid_to` set is closed. Loading a closed scene loads the world **as of the scene's `valid_from`**, and the context is marked `flashback: true`. An open scene loads current rows.
15. Scene events are derived: the events with `id > COALESCE(started_event_id, 0)` and, for a closed scene, `id <= ended_event_id`. `started_event_id` / `ended_event_id` hold the latest event id at the moment the scene began or ended (NULL if there were none). Recent events = the last 10 of those.
16. Recent narration = the narration text of the last 2 turns, read from `transcripts/turn-<N>.json`. Transcripts are gitignored local files, not world truth.
17. `Decision` queries carry the facts a backend needs (aspect text, slot, scene text, present names), so no backend needs database access. `Decision::decide` and `Generation::generate` both take `&mut Context`, so a local backend connects lazily with `chat::connect` and `Roles::load` is pure parsing.
18. Role strings: `local` (the project's selected model), `local:<id>` (allowed only when `<id>` equals the config's `model` or `endpoint_model`; otherwise an error when used), `rules`, `jev:<url>`. Narrator and archivist accept only `local` / `local:<id>`. Defaults: narrator `local`, archivist `local`, compel_decider `rules`.
19. Jev contract (no Jev spec exists): `POST <url>` with JSON `{"query": <DecisionQuery as JSON>}`, plus header `Authorization: Bearer $JEV_API_KEY` when that variable is set. The response is `{"yes": bool, "confidence": number, "reason": string|null}`.
20. The archivist runs **without tools**: it returns JSON `{"facts": [...]}`, Rust parses it (one retry with the error), asks the decider `Salient` per fact, and applies kept facts through the same world functions. If the answer is still invalid after the retry, or generation fails, the archive step emits a note and the turn goes on.
21. A turn is one SQLite transaction (`BEGIN IMMEDIATE` … `COMMIT`), guarded by a struct whose `Drop` runs `ROLLBACK` unless committed, so a panic or error leaves the previous turn. Each world operation runs inside a `SAVEPOINT` guarded the same way. `meta.json` is written to `meta.json.tmp` before `COMMIT` and renamed after it.
22. `meta.json` holds `name`, `created`, `turn`, `game_time`, `current_scene_id`, `roles`. No chapter and no PC count (both derived from the database). The session menu therefore shows `turn N · <game_time>`.
23. The session folder date is UTC (`web_util::utc_stamp`), not local time, so no timezone crate is added.
24. Menus and the turn prompt read whole lines (`BufRead`), not crossterm key events, so they are testable and work inside chat's `/rpg`.
25. `/back` closes the session (checkpoint, stop web, release lock) and returns to the menu; `/quit` does the same and leaves RPG mode.
26. The `events.jsonl` echo is **rewritten in full** from the database after each committed turn (`echo::render(db)`). `rebuild-echo` runs the same function, so the echo always matches.
27. On a failed `PRAGMA quick_check` at open, `world.vacuum` is copied over `world.db` (the `-wal` and `-shm` files are deleted first) and a warning is printed. If there is no backup, opening fails with a clear error.
28. The web scene buttons are `POST /scene/image` and `POST /scene/video` (they create files, so not GET). The scene-image and scene-video runners are function pointers on the web app, so tests can stub them.
29. The RPG web page has its own `assets/rpg.js`, because `assets/page.js` expects the chat page's mode radios and photo input.
30. The narrative renderer also shows `Kind::Error` lines, as `Something went wrong: …`, so a failed turn is not silent on a phone.
31. The RPG web handlers are tested at function level (`start_turn`, `run_scene_image`) plus pure render functions. No real HTTP server in tests, except the Jev stub.
32. `local` decision calls use the prompt `src/rpg/prompts/compel.md` for every query kind, with `temperature 0`, `no_thinking`, `max_tokens 200`, and the GBNF in `src/rpg/decision.gbnf`.

/// Forward-only migrations; migration N (1-based) brings `PRAGMA user_version` to N.
pub const MIGRATIONS: &[&str] = &[include_str!("schema.sql")];

/// Settings every connection needs: WAL journal and NORMAL sync. Ids are checked in Rust, not by foreign keys.

pub fn migrate(db: &rusqlite::Connection) -> Result<usize, String>;

  Rules for `configure`: `PRAGMA journal_mode=WAL` (read the returned row with `query_row`, because it returns one) and `PRAGMA synchronous=NORMAL`. On an in-memory DB the journal mode comes back `memory`; accept that.

Create the folder and `transcripts/`, take the lock, open `world.db`, `configure`, `migrate`, write meta (`turn 0`, `game_time START_TIME`, `current_scene_id None`, default roles, `name` = the PascalCase name), write an empty `events.jsonl`.
3. `list`: for each subfolder of `rpg_folder()` with a readable `meta.json` that parses, one `SessionSummary`, sorted by `dir_name` descending (newest first). It never opens a database. A missing rpg folder gives an empty list.
4. Lock: `OpenOptions::new().write(true).create_new(true)` on `.lock`, content `"{pid}\n{hostname}\n"`. Hostname is `/proc/sys/kernel/hostname` trimmed, or `unknown`. If the file exists, read it: if the pid is not alive (`!Path::new("/proc/{pid}").exists()`) or the content does not parse, print `taking over a stale lock from pid {pid}` to stderr, remove it and retry once. If the pid is alive: error `session {dir_name} is open in process {pid}`. `Drop` removes the file and ignores errors.
5. `open` order: (a) take the lock; (b) open the DB, `configure`; (c) `PRAGMA quick_check`. If opening, `configure`, or `quick_check` returns an error, or the first row is not `ok`: close the connection, delete `world.db-wal` and `world.db-shm`, copy `world.vacuum` over `world.db`, print `world.db failed its integrity check; restored the last backup` to stderr, and reopen. No backup: error `world.db is damaged and there is no backup ({BACKUP_FILE})`. (d) `migrate`; (e) read `meta.json`. In the restore case run (b)–(c) once more on the restored file; a second failure is an error.
6. `checkpoint`: remove `world.vacuum.tmp` if present, run `VACUUM INTO '<dir>/world.vacuum.tmp'` (pass the path as a bound parameter: `db.execute("VACUUM INTO ?1", [path])`), then rename it to `world.vacuum`.
7. `stage_meta` writes pretty JSON to `meta.json.tmp`; `finish_meta` renames it to `meta.json` and replaces `self.meta`.

9. `aspect_history(id)`: read the row's `chain_root_id`, then `WHERE chain_root_id = ?1 ORDER BY valid_from, id` (query shape 3).
