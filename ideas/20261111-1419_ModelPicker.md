# Model picker

Status: idea only. Not scheduled.

A model picker shows every local model ForgeFlow knows about (chat, image generation, image editing, video) in one place. From there you choose which model each role uses, download new ones, remove ones you no longer need, and see what fits on this machine's disk, RAM and GPU. It would be a native window (`forgeflow models --pick`) and a page in the web UI (`forgeflow serve`), both driven by the same Rust code.

## Why

Today models are managed through separate commands: `forgeflow models`, `forgeflow image`, `forgeflow image <id>`, `forgeflow pull <id>`, and the first-run wizard in `src/setup.rs`. That works, but some problems keep coming up:

- **Downloads are big and deliberate.** Models are not downloaded just in time. A word that needs a missing model fails with "`<id>` is not downloaded yet; run `forgeflow pull <id>`". That is on purpose: `wan2.2-vace-fun-nsfw` is about 32 GB across its files, `qwen-image-edit-2511` about 20 GB, and the 30B text model about 18 GB. At one point the disk was 96% full. Nothing currently shows the download size next to the free space before you start.
- **There is no way to remove a model.** You delete folders in `~/local-models` by hand, and that can break other models (see shared files below).
- **The scope of a setting is invisible.** Image settings live in each project's `_forgeflow/config.json`. A test project used the local image model while the main project still used OpenRouter, and nothing said so.
- **Shared files.** The 6 GB UMT5 text encoder and the Wan VAE are hard-linked between video models by `image_models::installed_copy`. Deleting one model's folder is safe only because of the hard link; a tool that removes files must know which other models still use them.
- **Repairs.** One GGUF needed its tensor shapes relabelled (`reshape`) after download before stable-diffusion.cpp would load it. If that step is interrupted or the catalog entry changes, there is no command to redo it.
- **GPU memory.** The chat model's llama-server is paused (`ops::pause_for`) while image, video and face-swap jobs run. Which models can be loaded together is not shown anywhere.
- **Uncatalogued models.** GGUFs you drop into `~/local-models/<name>/` yourself are found by `models::uncatalogued_local_models` but only appear in the text table.

## What you see

One list, grouped by role, with the current selection marked and a footer with disk and memory.

```

│  ○ qwen2.5-7b-q4km         4.7 GB  installed   fits   ~95 tok/s │
│  ○ my-merge (local file)   9.1 GB  installed   tight            │

│ GPU RTX 3090: 24 GB · RAM 64 GB                                 │
│ Chat + image edit at once: no (chat pauses during edits)        │
└─────────────────────────────────────────────────────────────────┘
```

Selecting a row opens details: files (flag, repo, path, size, installed/partial/missing, shared with which models), license, tags, steps/resolution, and actions. Sizes shown for a download are the bytes still needed, after counting files already present for other models ("shares 6.6 GB").

The scope switch shows whether you are editing this project's config or the default for new projects. When the project overrides the default, the row says so ("this project: OpenRouter; default: local").

A TUI version is not planned. The terminal keeps `forgeflow models` and `forgeflow image` as today, and they gain the same columns (status, shared bytes, partial %) where that is cheap.

## Actions

| Action | What it does |
|---|---|
| **Select** | Sets the role's field (`model`, `local_image_model` and `image_backend`, `local_edit_model`, `local_video_model`) in the chosen scope. Selecting a missing model offers to download it first. |
| **Download** | Shows the bytes needed, free disk after download, and the files involved; asks for confirmation. Refuses (with an override) when less than a margin, say 5 GB or 5%, would remain. Uses the existing `models::download` with its `.part` resume and sha256 check, then `reshape` for files that need it. |
| **Progress / cancel** | Progress per file and overall. Cancel stops after the current chunk and keeps the `.part` so the next download resumes. |
| **Resume / discard partial** | A model with `.part` files shows its percentage. Discard deletes the `.part` files. |
| **Remove** | Lists the files to delete and the bytes freed. Files still used by another installed model are kept, and the dialog says which model keeps them. Removing the selected model of a role warns and clears or changes the selection. |
| **Verify** | Re-hashes the installed files against the catalog sha256 (slow on big files; shows progress). A mismatch offers re-download of that file only. |
| **Repair** | Re-runs `gguf::reshape_in_place` for files with `reshape` entries (it is a no-op when the shapes already match), and re-links shared files that were copied instead of linked. |
| **Ask when first needed** | An opt-in setting. When a word hits a missing model, instead of failing it asks in the window or web page: "make-video needs wan2.2-vace-fun-nsfw (32.1 GB, 48.0 GB free). Download now?" Off by default; scripts and the CLI keep failing with the current message. |

## How it fits the code

### New module: `src/model_manager.rs`

The shared logic, with no UI in it. Both front ends call it.

```rust
pub enum Role { Chat, Image, Edit, Video }

pub enum Source { Text(CatalogModel), Media(ImageModel), Local(LocalModel) }

pub enum InstallState {
    Installed,
    Partial { have_bytes: u64 },
    Missing,
}

pub struct FileStatus {
    pub path: PathBuf,
    pub size_bytes: u64,
    pub state: InstallState,
    pub shared_with: Vec<String>,   // other catalog ids that list the same repo/path/sha256
}

pub struct Entry {
    pub id: String,
    pub roles: Vec<Role>,
    pub source: Source,
    pub files: Vec<FileStatus>,
    pub needed_bytes: u64,           // still to download, after shared files
    pub freed_bytes: u64,            // what Remove would free
    pub fit: Fit,                    // from models::estimate, or offload for video
}

pub struct Overview {
    pub entries: Vec<Entry>,
    pub selected: BTreeMap<Role, String>,
    pub scope: Scope,                // Project(PathBuf) | Default
    pub free_disk: Option<u64>,      // device::free_disk_bytes(models_dir())
    pub device: Device,
}

pub fn overview(project: &Path, scope: Scope) -> Overview;
pub fn plan_remove(id: &str) -> RemovePlan;   // files to delete, files kept and why
pub fn remove(plan: &RemovePlan) -> Result<u64, String>;
pub fn verify(id: &str, progress: &mut dyn FnMut(Progress)) -> Result<Vec<Mismatch>, String>;
pub fn repair(id: &str) -> Result<Vec<String>, String>;
```

The catalog is read through the existing `models::catalog()` and `image_models::catalog()`; nothing new is added to the JSON. `shared_with` generalises `installed_copy`: two catalog files are the same when `repo`, `path` and `sha256` match. Before deleting a file, `remove` checks both the catalog (is it listed by another installed model?) and the link count (`MetadataExt::nlink() > 1` on Unix), and keeps it if either says it is shared. The text catalog is included in this check too, since an image model's `--llm` file could one day be a text model's GGUF.

### Changes to existing modules

- `src/models.rs`: `download` takes a cancel flag and reports progress through a callback instead of only `&mut dyn Write`, so the window and web page can draw bars. `pull` keeps its current signature as a wrapper.
- `src/image_models.rs`: `pull` gains the same; `installed_copy` moves to (or is called from) `model_manager`. `render_table` can add the partial and shared columns.
- `src/config.rs`: a default config, for example `~/.config/forgeflow/config.json`, which `Config::load` uses as the base when the project has no file or leaves out a field. Today every project starts from `Config::default()`. This is the only real behaviour change and could ship on its own.
- `src/setup.rs`: the first-run wizard could open the picker window filtered to Chat when a desktop session exists, and keep the current terminal flow otherwise.
- `src/device.rs`: unchanged; `free_disk_bytes`, `gpu_free_bytes` and `model_budget_bytes` already give what the footer needs. "Which combinations fit at once" is computed in `model_manager` from these and the `pause_for` estimates in `ops.rs`.

### Native window

Reuse the `picker.rs` pattern: `forgeflow __models <json>` runs the window in its own short-lived process, because a process can create only one event loop and words run off the main thread. Unlike the point picker, this window runs for a while and starts downloads, so either the child does the downloads itself (simple; the parent only learns the final selection) or it streams progress lines on stdout. The first is enough: the child writes the config and prints the new selection as JSON on exit. Two windows downloading the same model are prevented by a lock file beside the `.part` file.

### Web page

A `/models` page in `src/web.rs`, rendered with maud like the chat page, using htmx for actions and the existing server-sent events stream for download progress. It is behind the same token check (`authorized`). Because the web UI can be opened from another device on the LAN, Download and Remove ask for confirmation in the page, and Remove could be limited to localhost.

### Tests

- `shared_with` and `plan_remove` against a temp `FORGEFLOW_MODELS_DIR` with fake files: removing one of two Wan models keeps the UMT5 encoder and VAE; removing the last one deletes them.
- Link count: a file with `nlink > 1` that no catalog entry claims is kept.
- `needed_bytes` subtracts shared files already installed and counts `.part` bytes as done.
- Default plus project config merge: a project field overrides, a missing field falls back.
- Download cancel leaves a `.part` that the next call resumes (with a local HTTP fixture, as the existing download tests do, if any; otherwise a file:// stub).
- Repair is idempotent: running `reshape` twice changes nothing the second time.

## Edge cases and risks

- **Deleting something still in use.** A model may be loaded by a running llama-server or sd-cli. Remove should refuse while the session's server uses it, and on Windows the delete would fail anyway.
- **Hard links across filesystems.** If `FORGEFLOW_MODELS_DIR` spans mounts, `hard_link` fails and `pull` copies. Then link counts say "not shared" while the catalog says it is; trusting the catalog check covers this.
- **Files changed outside ForgeFlow.** A user may replace a file by hand. Verify finds it; the overview should not hash on every open (too slow for 30 GB), only compare sizes.
- **Disk estimate is approximate.** Free space can change during a 30 GB download. Check again before each file and stop cleanly with the `.part` kept.
- **Fit for video is different.** Video models run with `--offload-to-cpu --mmap`, so "fits" means something else there; show "offload" rather than "no".
- **Uncatalogued models** have no sha256, no roles beyond Chat, and no size estimate beyond the file size. Verify is not offered; Remove deletes the folder after confirmation.
- **Catalog updates.** A new catalog version can change a file's sha256. The old file then shows as a mismatch, not as installed. Offer re-download, and do not delete the old file until the new one verifies.
- **Remote web users.** A phone on the LAN should not be able to fill the disk or delete models without the confirmation, and possibly not at all.

## Open questions

1. Is a global default config wanted, or should the picker only show per-project settings but make the scope obvious?
2. Should "ask when first needed" exist at all, given that large downloads were deliberately made explicit?
3. Should Remove be allowed from the web UI, or only from localhost and the native window?
4. Should text and media catalogs merge into one file, or stay separate with `model_manager` joining them?
5. Should the window also show programs (llama-server, sd-cli, FaceFusion from `toolchain.rs` and `facefusion.rs`) with their pinned versions and install size? FaceFusion alone is about 4 GB.
6. How should "fits together" be shown: a small matrix of roles, or one line for the current selections only?
